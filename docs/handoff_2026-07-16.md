## What changed today

### 1. Mapping (`bulk_dir_loader.py`) — the three items from yesterday's handoff
- **Near-match** (`_canon_col` / `_near_matches`) — canonicalize both names through a small
  abbreviation table, then require **exact** equality. `SRVY_ID`↔`survey_id`,
  `INCLINATION`↔`incl`, `AZIMUTH`↔`azim`, `TVDSS`↔`tvd`, `elev`↔`elevation`. Ambiguity in
  either direction → **no** proposal. Not token overlap. Not scoring.
- **Dropped-column warning** — `_stg_nonnull_counts` does one set-based query per staging
  table. A column that is provably 100% empty does **not** warn (that would train you to
  ignore the warning); `{}` from the query means UNKNOWN and still warns.
- **Rule/mapping mutual exclusion** — falls out of the ordering: near-match resolves first,
  so `_suggest_functions` never sees a required column a source can fill. Belt-and-braces
  enforcement at save time drops any rule whose target is mapped.

### 2. DLIS + LIS extractors — rewritten
Both had **the same five bugs**, all silent:

| bug | consequence |
|---|---|
| `*.dlis` + `*.DLIS`, no dedup | every log and curve emitted **twice** on NTFS |
| `log_id = f"LOG_{stem}"` | filename-derived → `curve_id` overflowed `nvarchar(40)` |
| no `curve_id` emitted | forced a `concat`/`seq_concat` rule that overflowed |
| `UWI`/`CURVE_NAME`/`RUN_NO` | pre-DDL names → mapped nowhere or needed rules |
| `files[0]` only | multi-logical-file DLIS/LIS **silently dropped** the rest |

LIS had two more: `break` after the first `data_format_specs()` (every pass but the first
dropped), and `run_num` hardcoded to `"1"`.

Fixes: `find_dlis()` / `find_lis()` dedup on `normcase(abspath)`; `curve_id =
entity_id(uwi, log_id, mnemonic)` — SHA1(UTF-16-LE, upper, trimmed), exactly 40 chars;
DDL-aligned lowercase columns; every logical file and pass walked; `files=`/`recursive=`
added; `depth_ouom` detected from the index channel; `_num()` for full-precision decimals.

**WITSML was NOT broken by the glob** — it wraps its globs in `set()`. Only DLIS had it.
LAS was fixed yesterday.

### 3. `_detect_logfmt` was throwing the file list away
```python
files = _ungated(_glob_ext(directory, [ext], recursive))   # gated, deduped, recursive
lp, cp, nl, nc = mod.write_staging_csvs(directory, ...)    # ...then ignored it
```
Three bugs from one line: re-read files the gate said to skip, missed subfolders on a
recursive scan, double-counted. Now routes through `_call_extractor`, which also warns
loudly when an extractor has no `files` parameter.

### 4. `load_router` — the pre-scan screen is gone
`route = ss.get("lr_route") or "B"`. Route B was the default for every folder, so the
router's directory box + "Scan & route" button just forwarded — and the counts it drew were
discarded by its own `st.rerun()` before they could render. The ⇄ switch and "Load another
folder" stay; those were its real value. `classify()` kept as a pure function.

### 5. New tools
- **`db_scorecard.py`** — read-only. Table inventory, NOT-NULL restore candidates, silent
  gaps (0% columns in populated tables), partial fill. **`--min-rows` defaults to 1; raise
  it.** Section 2 is unusable on small or synthetic data — "100% populated across 3 rows"
  proves nothing.
- **`repo_audit.py`** — duplicate modules, top-level reachability by entry point.
- **`find_refs.py`** — every reference to a directory name with file:line. Over-reports on
  purpose.

## Bugs I introduced today (and fixed)

Recorded because the pattern matters more than the bugs.

- **The UWI gate failed OPEN.** Realigning the extractors to lowercase DDL names broke four
  uppercase lookups (`d.get("LOG_ID")`, `d.get("UWI")`, `d.get("WELL_NAME")`,
  `if "UWI" not in hdr`). `_file_key` returned `""` → the file dict came out empty →
  `unresolved` was empty → the gate **returned True and let logs with no UWI stage**. It
  didn't error. It looked like it ran. Fixed with `_dget()` (case-insensitive), verified
  against both old and new row shapes.
- **Dropped `file_path` / `file_format` / `well_name`** from the extractor output by
  aligning the column list to LAS, with `extrasaction="ignore"` silently discarding them.
  `file_path`/`file_format` are real `dv_well_log` columns. Restored.
- **`.4g` on curve min/max.** Justified as "display-grade, precision doesn't matter" — but
  they're NUMERIC columns and the *format* matters: `1.527e+05` is an exponent
  `TRY_CONVERT` may reject, producing a silent NULL. `staging_qa` caught 47 in one run.
  Now `_num()` everywhere; zero `.4g` left (verified on the AST).

### 2. `log_id` is 37 of 40 characters
`LOG_A12-A-08_Run4_8375in_RM_600-1175m`. Three characters of headroom. One longer filename
and it's the same overflow that broke `curve_id`, in `log_id` this time.

**Do NOT change it to `LOG_<uwi>`.** The data disproves that: three logs share
`17015101080000`, two share `17015101190000`. A well has many logs. Also the UWI is blank
at extract time — that's what the gate is for — so `LOG_<uwi>` would never fire anyway.
Bound the stem, or hash it.

### 3. WITSML — untouched, entirely pre-DDL
`CURVE_NAME`, `RUN_NO`, `SRVY_ID`, `SURVEY_SEQ_NO`, `INCLINATION`, `AZIMUTH`, `TVDSS`,
`TOP_MD`. Near-match rescues `SRVY_ID`/`INCLINATION`/`AZIMUTH`/`TVDSS`; it will **not**
rescue `CURVE_NAME`→`mnemonic` or `TOP_MD`→`top_depth` (not abbreviation pairs).
`SURVEY_SEQ_NO` is hardcoded `"1"` for **every** station — if that maps to `station_id`,

## Environment — two real hazards

**Streamlit caches imported modules.** `_opt_import` runs once, at process start. Editing an
extractor while the app is running does **nothing** — `sys.modules` holds the old object.
This bit us four times in one session. **Restart the process; deleting `C:\Bulk\_*_extract\`
too, or a stale CSV looks like fresh output.**

**OneDrive is holding the repo.** The watchdog thread died today:
```
PermissionError: [Errno 13] Permission denied:
  '...\dataview\import_data\dlis_header_loader.py'
```
That's a **thread death**, not a caught error — the file watcher is gone for the rest of that
process's life, so no edit is ever detected. A plausible contributor to the deploy-staleness
that has shadowed this project. Mitigate now in `.streamlit\config.toml`:
```toml
[server]
fileWatcherType = "none"
```
Fix properly later: a git repo with a `venv\` inside OneDrive is a known bad combination —
locks files mid-write, rewrites underneath you, Files On-Demand can leave a file looking
present while its content is in the cloud. Move to `C:\dev\`.

**Windows hard-crashed twice** — all GUI apps gone, cmd windows survived, reboot required.
Unexplained. `perfmon /rel` will show whether it lines up with the DLIS runs. DLIS/LIS
extraction is the most memory-hungry thing the app does, and removing the LIS `break`
increased it.

## Facts worth not re-deriving

- **`relax_notnull_ddl.sql` ran 2026-07-15. Leave it. It is the schema now.**
  39 columns across **`dv_well_casing` (16), `dv_well_dst_period` (10), `dv_well_pressure`
  (13)** — *not* the survey or formation tables. **All three tables are empty**, so it
  unblocked nothing and risked nothing. It keeps NOT NULL on PK, `uwi`, `active_ind`,
  `source`, `row_created_by/date` and relaxes only measurements. That is a considered split
  and PPDM would agree: a casing record without a burst rating is a real casing record. The
  only ones arguably worth restoring are the discriminators — `casing_type`, `period_type`,
  `pressure_type`.
- **`GLOBAL_FILE_CATALOG` lives in `file_catalog`. Confirmed by `sys.tables` — ONE table,
  20 rows.** `sp_help` reports `Owner = dbo` because the *schema* is owned by `dbo`; that is
  not a second copy. (The four-database ambiguity was across databases, not schemas.)
- **`sp_help` lengths are BYTES.** `INVENTORY_ID nvarchar 80` = **40 characters**. Same for
  `curve_id`, `log_id`, `mnemonic`. All the 40-char `*_id` columns are sized for a SHA1 hex.
- **The canonical id recipe:**
  `hashlib.sha1(s.upper().strip().encode("utf-16-le")).hexdigest().upper()` — matches SQL
  Server `HASHBYTES('SHA1', UPPER(LTRIM(RTRIM(x))))`. Exactly 40 chars. Never UTF-8.
- **DLIS depths are in `0.1 IN`.** 152749 → 15,274.9 in → 1,272 ft. The values are honest
  and correctly labelled; nothing converts them.
- **A scout ticket lists formation tops only** — the base of one is the top of the next. The
  7 NULL `base_depth` rows are correct, not a bug.
- **PowerShell is not cmd.** `dir /s /b` → `Get-ChildItem -Recurse`; `rmdir /s /q` →
  `Remove-Item -Recurse -Force`; `.bat` needs `.\`. SQL goes in SSMS.
- **`ALTER COLUMN ... NOT NULL` is self-validating** — SQL Server refuses if a NULL exists.
  You cannot corrupt anything by trying.
- **`dv_column_map` now holds two generations** for `DV_WELL_FORMATION_TOP`: `TOP_MD` and
  `TOP_DEPTH` both → `top_depth`. Both active, both correct — a given staging table only
  ever has one. `source_file_pattern` is `'*'` on every row; scoping it to `*.dlis` etc.
  would kill a class of stale-rule pain for free.

## The pattern

Yesterday's note said it: nearly every bug is **silent**. Today added a sharper version —
**the silent bugs I fixed were replaced, twice, by silent bugs I introduced.** The UWI gate
failing open because a column changed case is *worse* than no gate, because it still looks
like it ran. `extrasaction="ignore"` quietly dropping three columns is the same move the
loader used to make.

The defence that actually worked was not care. It was **instrumentation**: `staging_qa`
caught the scientific notation; the scorecard caught the 0% columns; the ⚠ warning caught
`well_name`; and *the operator noticing a screen that didn't appear* caught the gate. Every
one of those was a machine or a human saying "this doesn't add up" — not a review.

So: **when something is skipped, say so. When something can't be recovered, refuse rather
than invent. And build the thing that tells you when you're wrong, because you will be.**

And the recurring own-goal, unchanged and committed again today: adopting a plausible
identifier from context without confirming it. `dbo` from an `sp_help` column that meant
something else. `TOP_MD` as the blocker when the tables didn't even intersect. 39 ALTERs
called "a suspiciously round blast radius" before reading which tables they touched.
**The schema is the contract. Ask.**
