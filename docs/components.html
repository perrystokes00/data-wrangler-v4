Component documentation

Seven parts,
one database

Data Wrangler is one application over a DataView database. Each part does a narrow job and hands off to the next, so you can adopt one without adopting all of them.

Below is what each part is for. Five have full technical documentation — the same documents the software was built against, covering what each component does, the decisions behind it, and what it deliberately refuses to do.

The database

Everything else writes into this.

DataView

A PPDM 3.9 derivative, reshaped for data that arrives messy. Wells, tops, surveys, completions, production, cores and petrophysics — plus geography columns, so the map reads shapes the database already agreed to. Ships with 3.9 million agency well headers loaded.

Read the documentation →

Getting data in

Three routes, chosen by what the data looks like rather than where it came from.

File Catalog

Point it at a folder and it works through everything in there: well logs, seismic, scout tickets, end-of-well reports, shapefiles. It identifies each format, pulls out what it can read, stages the rows, and loads the ones that pass. Anything it will not load is listed with the reason.

Read the documentation →

Data Assistant

For data that already has columns — spreadsheets and CSVs. It recognises a file by its shape, proposes a mapping from its columns to database fields, and works out the loading order so nothing is written before the record it depends on. You review the mapping before anything lands.

Read the documentation →

Document Assistant

For reports rather than tables. It reads a document, finds the tables inside it, names the columns it recognises and asks about the ones it does not. It writes nothing to the database — the point is to see what it understood before you decide to keep it.

Read the documentation →

Getting answers out

Once the data is in, three ways to ask it questions.

Mapping

For the questions you cannot phrase as a query — what is in this area, who operates it, which of these has a directional survey. Draw a box and you have a well list; open a well and you have its scout ticket and its documents; export the selection in whatever format the next tool needs.

Read the documentation →

DB Explorer

Query, browse and export any table in the database directly. It reads the schema as it actually is rather than from a stored snapshot, so it stays right when the database changes.

Covered in the DataView documentation

Reference Tables

The controlled vocabularies — well status, well type, units, depth datum, data source. Loading checks values against these, so an unregistered code holds its rows for review instead of quietly landing in your database.

Covered in the DataView documentation
